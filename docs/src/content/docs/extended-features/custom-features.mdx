## Package IDs for Extended Addressing

Package IDs enable 16-bit message addressing for large systems.

**When to use:**

- Systems with more than 255 messages
- Multi-package systems requiring namespace separation

**Frame compatibility:**
Use Extended or ExtendedMultiSystemStream payload types with package IDs.

**Message ID encoding:**

- Without pkgid: 8-bit (0-255)
- With pkgid: 16-bit = `(package_id << 8) | msg_id`

See [Message Definitions](/basic-usage/message-definitions/#message-options) for usage details.

## Minimal Frames (Bandwidth-Limited Scenarios)

Minimal frames remove length and checksum fields for lowest overhead.

**Requirements:**

- All messages must be fixed-size (no max_size, only size)
- Parser needs message length lookup function

The generator creates a `get_message_info` function automatically:

<Tabs>
<TabItem label="Python">

```python
from structframe.frame_profiles import BufferWriter, AccumulatingReader, PROFILE_SENSOR_CONFIG
from structframe.messages import get_message_info

# Encode using the sensor profile (Tiny + Minimal)
writer = BufferWriter(PROFILE_SENSOR_CONFIG, 1024)
writer.write(msg)
frame = writer.data()

# Minimal profiles have no length or checksum, so the reader needs the callback
reader = AccumulatingReader(PROFILE_SENSOR_CONFIG, get_message_info=get_message_info)
reader.add_data(frame)
result = reader.next()
```

</TabItem>
<TabItem label="C++">

```cpp no-compile
#include "frame_profiles.hpp"
#include "messages.structframe.hpp"

using namespace structframe;

// Encode using the sensor profile (Tiny + Minimal)
uint8_t buffer[1024];
ProfileSensorWriter writer(buffer, sizeof(buffer));
writer.write(msg);

// Minimal profiles need the message-info callback (they carry no length field)
ProfileSensorAccumulatingReader reader(get_message_info);
reader.add_data(buffer, writer.size());
FrameMsgInfo result = reader.next();
```

## Large Messages

For messages larger than 255 bytes, use a profile with a 16-bit length (Bulk or Network) when encoding:

```bash
struct-frame large.sf --build-c
```

## Variable-Length Encoding

Mark a message `[variable]` for efficient encoding of variable-length arrays or strings:

```sf
message LogEntry @10 [variable] {
  uint64 timestamp;
  string<256> message;
  vector<uint8, 128> data;
}
```

Only the bytes in use are transmitted instead of each field's full capacity. See [Message Definitions](/basic-usage/message-definitions/#attributes) for details.

## Variable Oneofs

A `oneof` with a discriminator inside a variable message transmits only the active variant's bytes by default ("trimmed" mode). Mark the oneof `[variable]` for a length-prefixed, forward-compatible format. The examples below use these payloads:

```sf
struct SmallPayload {
  uint8 a;
  uint16 b;
}

struct LargePayload {
  array<uint8, 32> data;
}
```

### Trimmed Mode (Default)

When the parent message is variable and the oneof has a discriminator (and is not `[variable]` itself), only the active variant's bytes are sent. The receiver derives the size from the discriminator:

```sf
message CommandMessage @20 [variable] {
  oneof data [discriminator = field_order] {
    SmallPayload small;  // 3 bytes on the wire when active
    LargePayload large;  // 32 bytes on the wire when active
  }
}
```

### Variable Mode (Length-Prefixed)

Mark the oneof `[variable]` to include a `uint16` length prefix, allowing receivers to skip unknown variants:

```sf
message LengthPrefixedCommand @21 [variable] {
  oneof data [discriminator = field_order, variable] {
    SmallPayload small;  // only its own bytes transmitted
    LargePayload large;  // only its own bytes transmitted
  }
}
```

**Wire format:** `[discriminator][uint16 length][variant_bytes]`

### Controlling Oneof Size

**`max_size = N`** — valid on **non-variable (trimmed) oneofs only**. Reserves `N` bytes in the in-memory struct union for future variants without changing the wire size of current variants:

```sf
message Reserved @40 [variable] {
  oneof data [discriminator = field_order, max_size = 64] {  // 64-byte in-memory buffer
    SmallPayload small;  // Still 3 bytes on the wire
  }
}
```

**`min_size = N`** — valid when the parent message is `[variable]` **and** the oneof is either `[variable]` or the only variable-length (trimmed) member of the message. Pads the wire payload to at least `N` bytes for backward compatibility:

```sf
message Padded @41 [variable] {
  oneof data [discriminator = field_order, variable, min_size = 8] {  // at least 8 bytes
    SmallPayload small;  // 3 bytes → padded to 8 bytes on the wire
    LargePayload large;  // 32 bytes → transmitted as-is
  }
}
```

> **`max_size`** applies to non-variable (trimmed) oneofs — it reserves in-memory space without affecting wire size per variant.
>
> **`min_size`** applies to variable or trimmed oneofs in variable messages — it pads the wire payload and cannot exceed the oneof's buffer size.

See [Variable Oneofs](/basic-usage/message-definitions/#variable-oneofs) in Message Definitions for the complete reference.
